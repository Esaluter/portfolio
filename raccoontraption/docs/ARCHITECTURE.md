# Архитектура Raccoontraption

## Общая схема

Raccoontraption — клиентское React-приложение. React Flow отображает граф, `App.tsx` управляет состоянием и историей, а чистый execution engine проверяет связи и вычисляет значения независимо от React.

```text
src/
├── main.tsx
├── App.tsx                     # состояние, команды, Undo/Redo и интеграция engine
├── types.ts                    # GraphValue, операции и типы семи узлов
├── components/
│   ├── BlockCatalog.tsx        # сворачиваемый каталог блоков по категориям
│   └── DemoGallery.tsx         # модальная галерея и подтверждение замены
├── examples/
│   ├── demoGraphs.ts           # четыре стабильных графа в формате JSON v1
│   ├── prepareExampleLoad.ts   # проверка и подготовка атомарной загрузки
│   └── demoGraphs.test.ts      # валидность, persistence и история примеров
├── graph/
│   ├── nodeFactories.ts        # фабрики узлов с защищённой генерацией ID
│   ├── createUniqueId.ts       # уникальные ID с учётом импортированного графа
│   └── findFreePosition.ts     # размещение на свободной позиции
├── engine/
│   ├── evaluateGraph.ts        # вычисление значений и технических ошибок
│   ├── connectionRules.ts      # типы портов, handles и ограничения связей
│   ├── clearEvaluationState.ts # очистка устаревших результатов
│   ├── errorMessages.ts        # стабильные пользовательские сообщения
│   ├── evaluateGraph.test.ts   # регрессионные тесты этапа A
│   └── stageB.test.ts          # тесты Random, Compare, Logic и типов
├── persistence/
│   ├── types.ts                # DTO v1, лимиты и результаты импорта
│   ├── serializeGraph.ts       # явная сериализация параметров графа
│   ├── validateGraph.ts        # структурная и предметная валидация
│   ├── deserializeGraph.ts     # разбор JSON и восстановление runtime-узлов
│   └── persistence.test.ts     # тесты round-trip и защиты импорта
├── indicator/
│   ├── getIndicatorPresentation.ts # чистая модель STATUS/GAUGE/EMPTY/ERROR
│   ├── IndicatorVisual.tsx     # общее визуальное представление
│   └── indicator.test.ts       # engine, соединения и визуальные состояния
├── preview/
│   └── PreviewPanel.tsx        # сворачиваемая панель всех Indicator
└── nodes/
    ├── NumberBlock.tsx
    ├── MathBlock.tsx
    ├── RandomBlock.tsx
    ├── CompareBlock.tsx
    ├── LogicBlock.tsx
    ├── OutputBlock.tsx
    ├── IndicatorBlock.tsx
    ├── PortRow.tsx             # единая строка подписанного входного/выходного порта
    └── NodeError.tsx           # компактное сообщение и tooltip причины
```

## Модель значений и узлов

`GraphValue` определён как `number | boolean`. Ошибка и пустой результат не являются значениями. Engine внутренне различает успешное значение, пустой результат и ошибку.

Типы данных узлов:

- Number: числовой `value`;
- Random: `min`, `max` и последний числовой `value`;
- Math: числовой результат и арифметическая операция;
- Compare: boolean-результат и операция сравнения;
- Logic: boolean-результат и логическая операция;
- Output: `GraphValue | null`.
- Indicator: `GraphValue | null`, режим, подпись и диапазон шкалы.

Каждый узел также хранит пользовательское сообщение `error` и техническое пояснение `errorDetails`. Callbacks параметров временно добавляются в данные при передаче узлов в React Flow и не являются частью вычислений.

## Порты и совместимость

`connectionRules.ts` описывает только фактически существующие блоки:

- Number, Random и Math выдают `number`;
- Compare и Logic выдают `boolean`;
- Math принимает любое количество числовых связей;
- Compare принимает по одному числу в именованные входы `a` и `b`;
- Logic принимает по одному boolean в `a` и `b`, а NOT использует только `a`;
- Output и Indicator принимают одно значение любого поддерживаемого типа;
- Indicator использует именованный вход `value`;
- Number и Random не имеют входов, Output и Indicator не имеют выхода.

Проверяются существование узлов и handles, совместимость типов, занятость одиночного входа и полные дубликаты связей. Compare и Logic используют общий `PortRow`: подпись и `Handle` находятся в одной относительной строке, поэтому порт остаётся напротив своего входа при изменении содержимого блока. При переключении Logic на NOT связь B удаляется одним действием истории; при возврате к двухвходовой операции порт B снова отображается. После изменения набора handles Logic вызывает `useUpdateNodeInternals`, чтобы React Flow пересчитал геометрию портов.

Проверка выполняется дважды: UI отклоняет недопустимое соединение до `addEdge`, а engine повторно валидирует весь переданный граф. Поэтому некорректные данные, попавшие в engine в обход интерфейса, превращаются в контролируемую ошибку.

## Выполнение графа

`evaluateGraph(nodes, edges, options?)` не мутирует входные массивы и возвращает:

- `values: Record<string, GraphValue | null>`;
- `errors: Record<string, EvaluationError>`.

Необязательная функция `options.random` позволяет подменить RNG в тестах. В приложении используется `Math.random`.

Во время запуска engine:

1. Проверяет связи и строит список допустимых входов.
2. Рекурсивно вычисляет зависимости.
3. Кэширует исход каждого узла, поэтому Random вычисляется один раз за запуск даже при нескольких потребителях.
4. Обнаруживает циклы по активному пути обхода.
5. Проверяет тип каждого фактического значения без приведения boolean к number и обратно.
6. Возвращает структурированные ошибки; независимые ветви продолжают вычисляться.

Indicator получает значение единственного источника без преобразования типов. AUTO выбирает представление по фактическому типу, STATUS принимает только boolean, GAUGE — только number. Engine проверяет конечный диапазон `min < max`, совместимость режима и распространение ошибок, но не рассчитывает цвета или CSS шкалы.

## Indicator и Preview

`getIndicatorPresentation` является чистой UI-функцией. Она превращает вычисленное значение и настройки в одно из состояний `status`, `gauge`, `empty` или `error`; заполнение GAUGE ограничивается 0–100%, исходное число не изменяется. `IndicatorVisual` одинаково отображает эту модель внутри блока и в Preview.

`PreviewPanel` получает актуальные узлы из `App.tsx`, фильтрует Indicator и не запускает engine. Поэтому удаление, импорт, Undo/Redo и новый Run автоматически отражаются в панели без отдельного хранилища результатов.

Новый вызов `evaluateGraph` создаёт новый кэш и заново запускает Random. Совпадение случайных результатов двух запусков допустимо.

## Компоновка редактора

`App.tsx` собирает верхнюю панель действий и рабочую область из `BlockCatalog`, React Flow canvas и `PreviewPanel`. Обе боковые панели отдают canvas место при сворачивании; на узких десктопных ширинах развёрнутые панели располагаются поверх canvas. Верхние действия остаются одной строкой и при нехватке места прокручиваются горизонтально.

Каталог только вызывает существующие фабрики узлов, поэтому поиск свободной позиции, история и очистка результатов работают так же, как раньше. Пустое состояние находится поверх canvas только при отсутствии узлов и предлагает открыть галерею либо создать Number.

## Семантика блоков

- Random принимает только конечные целые `Min ≤ Max` и генерирует целое число в замкнутом диапазоне.
- Compare использует handles A/B как порядок операндов и строго сравнивает два числа.
- AND, OR и XOR проверяют оба обязательных входа; short-circuit не используется.
- NOT требует только A.
- Output показывает number или boolean.
- Indicator/AUTO выбирает STATUS для boolean и GAUGE для number.
- Indicator/STATUS не преобразует number в boolean; Indicator/GAUGE не преобразует boolean в number.
- Math сохраняет прежний порядок вычитания и деления по порядку массива связей.

## Ошибки

Engine использует стабильные коды: `cycle`, `division-by-zero`, `invalid-number`, `dependency-error`, `input-unavailable`, `type-mismatch`, `invalid-random-range`, `invalid-indicator-range`, `indicator-mode-mismatch` и `invalid-connection`.

`errorMessages.ts` отдельно преобразует код в короткую неизменяемую енотовую фразу. Техническое сообщение engine помещается в `title` сообщения блока. Для неизвестного кода есть нейтральный fallback.

После исправления причины новый запуск заново формирует значения и ошибки, поэтому устаревшая ошибка исчезает.

## Состояние и Undo/Redo

Узлы и связи хранятся через `useNodesState` и `useEdgesState`. История использует два стека полных снимков `{ nodes, edges }`, созданных через `structuredClone`; undo-стек ограничен 100 состояниями.

В историю входят создание и соединение блоков, изменение параметров и операций, удаление, перемещение и контролируемое удаление B-связи при выборе Logic/NOT.

После смыслового изменения параметров, состава узлов или связей `clearEvaluationState` очищает значения всех вычисляемых узлов и прежние ошибки. Number сохраняет новое исходное значение. Результат снова появляется только после ручного Run; перемещение и выделение блоков вычисления не инвалидируют.

Успешный импорт или загрузка примера сначала сохраняет текущий снимок, затем одной операцией заменяет узлы и связи. Поэтому Undo возвращает граф до загрузки, а Redo повторно применяет импорт или пример. Невалидные данные не изменяют ни граф, ни историю.

## Формат сохранения и импорт

Persistence-слой не зависит от React-компонентов и использует явный DTO:

```json
{
  "format": "raccoontraption",
  "version": 1,
  "nodes": [],
  "edges": []
}
```

Узел содержит только `id`, `type`, координаты `position` и редактируемые параметры в `data`: `value` для Number, `operation` для Math/Compare/Logic, `min`/`max` для Random, `label`/`mode`/`min`/`max` для Indicator и пустой объект для Output. Связь содержит `id`, `source`, `target`, `sourceHandle` и `targetHandle`. Runtime-значения вычисляемых блоков, ошибки, callbacks, выделение и внутренние поля React Flow не входят в файл.

`deserializeGraph` ограничивает файл 1 000 000 байтами, разбирает JSON и передаёт неизвестные данные в `validateGraph`. Проверяются формат и версия, точная структура, типы и параметры семи блоков, уникальность ID, конечные координаты в диапазоне ±1 000 000, существование узлов, канонические handles, типы значений, занятость входов и дубликаты связей. Добавление Indicator является совместимым расширением допустимых узлов JSON v1: старые файлы без него остаются валидными. Допускается до 1 000 узлов и 5 000 связей. Цикл является допустимой структурой и обрабатывается execution engine при Run.

Только после полной успешной проверки DTO преобразуется в runtime-узлы. Вычисленные значения и ошибки очищаются, а callbacks заново добавляются адаптацией в `App.tsx`. Run автоматически не выполняется.

## Demo Gallery

`demoGraphs.ts` хранит четыре определения `SavedGraphV1` со стабильными ID: «Кубик судьбы», «Детектор удачи», «Логическая лаборатория» и «Машина вычислений». `prepareExampleLoad` сериализует определение и передаёт его в существующий `deserializeGraph`, поэтому структура, параметры, handles и типы связей проверяются теми же правилами, что и внешний файл.

До успешной проверки текущий граф не изменяется. После неё `App.tsx` сохраняет глубокую копию прежнего состояния в undo-стек, устанавливает очищенный runtime-граф, закрывает диалог и вызывает React Flow `fitView` после обновления DOM. Автоматического Run нет. Для непустого графа `DemoGallery` требует явного подтверждения; Escape закрывает диалог, а горячие клавиши редактора во время его показа игнорируются.

## Известные ограничения

- Порядок операндов существующего Math/Subtract и Math/Divide зависит от порядка связей и не представлен отдельными A/B-портами.
- Система портов описывает текущие семь блоков и пока не является универсальным реестром типов.
- Результаты пересчитываются только вручную кнопкой «Запустить».
- Preview показывает только текущий снимок последнего Run; истории запусков и временных графиков нет.
- Автосохранения нет: без явного экспорта несохранённые изменения теряются при перезагрузке.
- Импорт поддерживает только формат `raccoontraption` версии 1; миграций между версиями пока нет.
- Хранение остаётся файловым и локальным: облака, сервера и каталога проектов нет.
- Галерея содержит четыре встроенных примера; добавление, сохранение и синхронизация пользовательских шаблонов не реализованы.
- Адаптивность ориентирована на десктоп от 1024 px; полноценного мобильного редактора нет.
- Ограничения импорта: 1 000 000 байт, 1 000 узлов, 5 000 связей и координаты в пределах ±1 000 000.
- Отдельной панели диагностики нет; ошибки отображаются в блоках.
