# Инструкции для AI-агентов

Главный принцип: документация должна соответствовать реальному состоянию проекта, а не предполагаемому.

## Правила работы

1. Перед выполнением задачи изучайте соответствующий код и документацию.
2. Работайте в пределах поставленной задачи.
3. Не выполняйте несвязанный рефакторинг.
4. Не добавляйте зависимости без необходимости.
5. Сохраняйте совместимость существующих функций, если задача не требует изменения поведения.
6. После изменения кода обновляйте затронутую документацию.
7. При добавлении или изменении блока обновляйте `docs/BLOCK_CATALOG.md`.
8. При изменении архитектуры обновляйте `docs/ARCHITECTURE.md` и при необходимости `docs/DECISIONS.md`.
9. При изменении планов обновляйте `docs/ROADMAP.md`.
10. При изменении пользовательских возможностей актуализируйте `README.md`.
11. Ведите `docs/DEVELOPMENT_LOG.md` по датам, размещая новые записи сверху.
12. Записывайте в журнал только реально завершённые изменения.
13. Указывайте фактически выполненные проверки и их результаты.
14. Не заявляйте о прохождении ручного smoke-test без подтверждения пользователя.
15. Не выдавайте запланированную функциональность за реализованную.
16. Не изменяйте исторические записи без явной необходимости и согласования.
17. В конце каждой задачи предоставляйте краткий отчёт: изменённые файлы, реализованные изменения, проверки, обновлённая документация и оставшиеся ограничения.
